# Generate Test Notes

## 目标

把代码变更转成测试可执行的说明，不输出代码评审结论。生成两列 **TSV**（制表符分隔）文件并保存至文档，方便测试同学直接导入或复制到 Excel / 飞书 / 语雀表格。

**对话回复中无需输出 TSV 原文**，只需确保完整 TSV 正确写入文件，并在回复中给出文件链接与简要改动概述。

## 工作流

1. 明确变更来源：
   - 本地修改：读取 `git status --short`、暂存与未暂存 diff。
   - 指定提交：读取 `git show --stat --name-status <sha>` 和关键 diff。
   - 提交范围：读取 `git log --reverse --stat --name-status <base>..<head>` 和 `git diff <base>..<head>`。
2. 优先运行本 skill 的脚本收集上下文：

```bash
python3 .agents/skills/generate-test-notes/scripts/collect_change_context.py --local
python3 .agents/skills/generate-test-notes/scripts/collect_change_context.py --rev abc123
python3 .agents/skills/generate-test-notes/scripts/collect_change_context.py --range abc123..def456
```

3. 结合 diff、文件路径、提交信息、路由/API/Model/UI 文案变化，归并为面向产品行为的修改点。
4. 给每个修改点写测试注意事项，覆盖入口、前置状态、关键断言、边界条件、回归范围。
5. 若证据不足，写“需确认：...”或“建议回归：...”，不要编造不存在的行为。

## 归并规则

- 按用户可感知行为归并，不按文件逐条罗列。
- 多个文件共同实现同一流程时合并成一个修改点。
- 同一功能下的 UI、接口、缓存、埋点变化可放在同一行，但测试注意事项要覆盖各自风险。
- 版本号、依赖、权限、路由、深链、支付、登录态、本地数据迁移、缓存、分页、多语言、明暗主题、横竖屏、平板适配、错误态、空态、灰度开关要单独关注。
- 纯重构如果可能影响行为，写成“某流程重构/替换实现”；如果确认无行为变化，写“建议回归相关入口”。
- 只改注释、日志、格式化且无行为风险时可以省略，或在最后用一句“未列出纯工程调整”说明。

## 测试注意事项写法

每条注意事项尽量包含：

- 入口：从哪里触发，例如首页 Tab、设置页、登录弹窗、支付页。
- 前置：登录/未登录、会员/非会员、首次安装/覆盖安装、网络异常、列表数据量、App 语言、设备类型。
- 断言：页面展示、按钮行为、接口参数、Toast/Dialog、数据保留、跳转目标。
- 边界：快速点击、重复进入、横竖屏切换、分页/空列表、弱网、覆盖安装、回退路径。
- 回归：该改动可能影响的旧流程。

## 输出规范

- **文件输出（TSV）**：
  - 必须将完整内容以两列 **TSV**（制表符分隔）格式写入 `docs/改动点/<起始日期>_<起始时间>到<结束日期>_<结束时间>.tsv`。
  - 时间精确到时分，**即使起止同一天也要写全两侧日期**，如 `2026-08-11_10-33到2026-08-11_17-09.tsv`。
  - 时间范围取变更来源的最早/最晚时间：提交或提交范围取最早与最晚提交时间；本地未提交修改取相关文件 mtime 范围（无法确定时用当前时间）。若用户指定了路径则写到指定位置。
  - 文件采用 UTF-8 编码，包含表头行 `修改点\t测试注意事项`。
  - 列之间用 **Tab**（`\t`）分隔；单元格内不得包含 Tab 或换行符。
- **对话回复规范**：
  - **回复中禁止输出 TSV 代码块或大段制表符文本**，文档中已有完整数据即可。
  - 对话中只需输出：
    1. 生成的 TSV 文件链接（如 `[xxx.tsv](file:///...)`）。
    2. 面向人类阅读的简短修改点列表与核心测试要点（使用简洁的 Markdown 列表呈现，便于速览）。
    3. 纯工程调整若有，一句话说明即可。

## 质量要求

- 输出必须是给测试同学直接使用的清单，不解释 git 命令过程。
- 每行只写一个可测试的行为主题。
- 不把内部类名当成唯一修改点；类名只能作为括号补充。
- 有不确定性时显式标记，不隐藏风险。
- 不要为了生成清单而修改业务代码。
