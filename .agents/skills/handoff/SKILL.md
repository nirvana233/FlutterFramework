# Handoff

## 目标

把当前这段对话压缩成一份**结构化交接文档**，存到系统临时目录，让一个全新的会话（或另一个 agent）读完即可接着干，不必重读整段历史。

适用场景：

- 会话太长想开个干净的新会话省 token，但又不想丢上下文
- 把当前进度交接给另一个 agent / 同事接手
- 阶段性收尾，主动留一份"我做到哪了"的快照

> 与 Claude Code 自带的上下文自动压缩不同：那是同会话内续命、你看不到；本 skill 产出一份**落地、可读、可手改、可转交**的 `.md` 文件。

## 输出位置

**存到系统临时目录，不要写进工作区**（避免污染 repo / git）。macOS / Linux 用 `$TMPDIR`，兜底 `/tmp`：

```bash
echo "${TMPDIR:-/tmp}"
```

文件名建议带时间戳，如 `handoff-<项目名>-20260609-1530.md`，并在最后把绝对路径告诉用户。

## 文档必含内容

1. **任务目标** —— 这段会话在做什么、想达成什么
2. **当前进展** —— 已完成 / 进行中 / 尚未开始，分清楚
3. **关键决策与约束** —— 为什么这么做、踩过的坑、不能动的边界
4. **下一步** —— 接手者第一件该做的事，按优先级列
5. **相关产物索引** —— 改了哪些文件、相关分支 / commit、PRD / plan / issue 链接（见下"不重复"原则）
6. **Suggested skills** —— 列出接手的 agent 大概率要触发的 skill（如 `figma-ui`、`modify-ui`、`project-rules`、`network-request` 等），帮它快速进入状态

## 原则

- **不重复已有产物** —— PRD、plan、ADR、issue、commit、diff 里已经写清楚的，只用**路径或 URL 引用**，不要抄一遍。文档是"索引 + 上下文"，不是"全量复制"。
- **脱敏** —— API key、密码、token、个人隐私信息一律不写进文档。
- **带参数裁剪** —— 用户若说明了下一会话的焦点（如"下一轮专注做支付联调"），按这个方向裁剪文档，突出相关上下文、略去无关分支。
- **遵循项目规范** —— 文档可用中文；引用代码位置用 `文件路径:行号` 方便点击。

## 流程

1. 回顾当前会话，提炼上述六块内容
2. 取临时目录路径，确定文件名
3. 用 Write 写入交接文档
4. 把生成的绝对路径回报给用户，并一句话说明新会话怎么用它（如"新会话里让我先读这个文件"）
